# 07 — Whole-App Feature Preservation and Change Register

## Binding rule

The redesign changes presentation, hierarchy, and navigation labels. It does not authorize removing product capabilities, scientific functions, routes, data products, or admin tools.

Every proposed change must have a written reason and name what stays available. A collapsed panel, moved action, renamed label, or altered default is still a change and must appear in the register below or be added with the same level of detail before implementation. If a developer believes a feature must be removed, document the exact feature, users affected, scientific/product impact, alternative, and rollback path; leave it in place until the product owner approves that removal.

This document is subordinate to AGENTS.md and immutable SPECIFICATION.md. It is a frontend design handoff, not authorization to change APIs, calculations, data, URL contracts, or role-owned files.

### Clarifications for science previews

Retain the capability to preview a target when live data is unavailable, but keep the displayed source honest. The current code has deterministic preview paths in App.tsx:48–124 and SpectrophotometricLab.tsx:66. Such a preview may not be deleted solely because it is synthetic; it must carry the required synthetic/illustrative source label and must not be presented as an archive extraction. The same rule applies to seeded forum examples and synthetic SPLICES entries.

Do not replace a hidden or collapsed scientific control with a non-interactive illustration. A moved control must remain usable, keyboard accessible, and reachable without leaving the active workspace.

## Non-negotiable invariants

- Keep tab query values navigator, comparator, spectral, ice, and discussions and all current URL keys. A navigation label may change; existing deep links must continue to resolve.
- Keep /explore and /admin isolated. Do not move admin tools into the public navigation.
- Keep the five mandatory benchmark targets and universal coordinate/name search.
- Preserve data source honesty, source badges, wavelength-matched difference rules, raw Float32 science arithmetic, and real discrete observation timestamps.
- Preserve existing observer mutation headers and server-authoritative moderator badges.
- Do not add a package, change a database/API contract, alter a scientific formula, or silently change a default that affects results.
- Keep all current features reachable from the new layout, including on phone and keyboard-only navigation.
- Do not delete a feature because it is advanced, used less often, or difficult to fit above the fold.
